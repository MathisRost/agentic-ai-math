# Astra exact reciprocal-simplex experiment

Prepared for the owner on 20 October 2026. This is a clean derivative of the
earlier research setup, not a continuation of its results. Opening this folder
or preparing it does not launch agents. Only the owner's explicit START request
launches research.

1. The initial target is exactly `common/problem_statement.md`, version S0.
   Equalities, not asymptotics, approximations or connected densities, govern.
   Initially there are no scale/shape cutoffs and no finite-fourth-moment
   assumption. Prescribed positive intensity is retained.
2. Use `gpt-6-astra`, `xhigh`, for the coordinator and EVERY delegated role.
   Do not silently substitute another model. A saved config does not switch
   an already-running coordinator. Check model access and record the evidence
   before research. If unavailable or unverifiable, report it before proceeding.
3. Follow `workflow.json` and `instructions/coordinator.md`. Start with TWO
   independent non-existence agents. A fresh reviewer audits each frozen
   submission before any obstruction-driven target change is adopted.
4. Only the coordinator dispatches. Use fresh contexts, explicit file packets
   and assigned output paths. Never fork the full coordinator/author history
   into independent proof or review work. These are cooperation rules, not
   operating-system isolation.
5. Only reviewed general obstructions can justify coordinator-led domain
   revisions. A class-specific failure cannot restrict the general target.
   Explain the exact logical consequence and any non-unique choice of repair.
   A finite-moment obstruction cannot silently constrain the broader S0 class.
6. Separately, after THREE unsuccessful reviewed construction submissions, an
   agent MAY ask the owner to approve a precise target change. A proposal is
   not approval. Until an explicit owner response, the old target remains.
   An owner-approved amendment is recorded separately from a proved necessity.
7. Each construction approach has FOUR substantive submissions total: initial
   submission plus three repairs. A weaker result is partial progress, never
   an exact-target pass. No automatic retry reset after a target amendment.
   After four failures, label the approach unsuccessful, not the theorem false.
8. Freeze S0, subsequent statements, source additions, submissions, reviews,
   approved changes and dispatch packets with hashes. Preserve all versions.
   Send each adopted target version and its authority/evidence to EVERY role.
   Do not leak one construction track's new ideas to another.
9. Non-existence agents must NOT read `starting_information/`, old runs, other
   tracks or the owner's other chats. Construction agents may receive the same
   frozen starting-information packet after the obstruction phase. Its proofs
   are prior leads to verify, not accepted results of this experiment.
10. Save all new work under `runs/<run_id>/`. Keep the setup and original project
    unchanged during a run. Readers receive frozen proofs, not private notes.
    Reviews must be extensive, with negative results and unresolved obligations.
11. Record per-agent/per-turn token usage whenever runtime telemetry exposes it;
    use NR when unavailable, never invented counts. Complete the accounting
    preflight before launching research; see `instructions/accounting.md`.
    Supply explicit proofs and concise reasoning/decision summaries, NOT raw
    private chain-of-thought. Separate measured usage, estimates and charges.
12. Use the proof/review skills where applicable and the literature skill for
    precise source gaps. Numerical checks and earthquake-data comparisons are
    separate from proof. No unrequested simulation campaign or publication.
